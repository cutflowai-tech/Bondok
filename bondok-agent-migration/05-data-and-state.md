# البيانات والحالات

## الحد الأدنى المنطقي للبيانات
يمكن إعادة استخدام جداول موجودة؛ القائمة ليست أمرًا بإنشاء جداول جديدة لكل سطر.

| السجل | ما يحفظه |
|---|---|
| Items | معرف العنصر، حسابه، روابط Monday/Dropbox، أحدث إصدار |
| Versions | نسخة الملف، البصمة، الكابشن، الفورمات، الملف الجاهز |
| Commands | هوية المصدر، request_id، الطلب، النتيجة، مرجع العملية |
| Policies | القواعد وإصداراتها ونطاقها ووقت سريانها |
| Overrides/Attestations | الاستثناءات وتأكيدات المالك، مع التمييز بينهما |
| Reservations | الحساب، الموعد، نوع المحتوى، المهمة المرتبطة |
| Jobs | موعد التنفيذ، الحالة، عدد المحاولات، الحجز المؤقت |
| Publish attempts | النسخة، بصمة payload، معرف container، مرحلة الإرسال، الدليل |
| Outbox | تحديثات الواجهات والتنبيهات المطلوب تسليمها |
| Audit | من قرر ماذا ومتى والنتيجة ومصدر الإثبات |

احفظ التوقيت بصيغة UTC مع منطقة العرض Africa/Cairo؛ حساب المواعيد المحلية يستخدم قاعدة المناطق الزمنية وليس إزاحة ثابتة. تعريف تفرّد الحجز يتبع سياسة الحساب ونوع المحتوى؛ لا تفرض منع كل نشرين في نفس اللحظة كحقيقة منصة إذا كان مجرد قرار عمل قابل للتغيير.

## دورة المحتوى
مسودة → تجهيز → جاهز → مجدول → جارٍ النشر → منشور.

سبب التعطل وطلب الإيقاف حقول مستقلة؛ محاولة النشر لها حالة مستقلة: مجهزة، قبل الإرسال، الإرسال قد بدأ، مؤكدة النجاح، مؤكدة الفشل، غير محسومة. مصطلح «فشل مؤكد» يحتاج دليلًا مناسبًا لمرحلة الطلب واستجابة المنصة؛ لا تستخدم تصنيفًا عامًا لكل 4xx بدون مراجعة دلالته.

## نقطة الإرسال والإلغاء
داخل معاملة محلية: اقرأ آخر أمر مقبول، تحقق من النسخة والتفويض، واحجز المحاولة وسجّل الانتقال إلى «الإرسال قد يبدأ». أي طلب إيقاف مقبول قبل هذا الانتقال يمنع الإرسال. بعده يعرض النظام أن الإيقاف غير مضمون؛ قد يكون الطلب الخارجي خرج بالفعل. لا تدّعِ أن local commit يقفل الأنظمة الخارجية.

إغلاق السيرفر بعد تسجيل هذه المرحلة وقبل حفظ الرد يؤدي إلى المصالحة، وليس إرسالًا جديدًا تلقائيًا. لا نعتمد على idempotency من المنصة إلا إذا تحقق دعمها للعملية المعنية.

## تغير النسخة
تأكيد Topaz مرتبط بالنسخة التي قصدها المالك. الملف المعدل ينتج نسخة جديدة، ويظهر سؤال عن شمول التأكيد لها إذا لزم. الاسم لا يلغي التأكيد. تغيير الكابشن لا يلغي معالجة الفيديو؛ يبطل فقط ما يعتمد فعليًا على الكابشن. النسخة الجاهزة المستخدمة في محاولة بدأت لا تستبدل في منتصف التنفيذ.

## مصالحة النشر
راجع أدلة المنصة التي تم التحقق من معناها رسميًا. container جاهز للمعالجة ليس وحده دليل أن المنشور أصبح حيًا. إذا تعذر الحسم، احتفظ بالحالة وأرسل للمالك ما يلزم مراجعته. يستطيع تسجيل تأكيد يدوي برابط أو قرار إعادة محاولة واعٍ باحتمال التكرار؛ يسجل مصدر القرار دون تزوير دليل API.

## سياسة الانقطاع
- تعطل تحديث عرض Monday: احتفظ بالنتيجة وأعد تسليم التحديث.
- تعطل استقبال طلباته: طبق سياسة حداثة البيانات التي يختارها المالك في P1؛ لا تفرض منع نشر دائم غير قابل للتغيير.
- تعطل الموديل: تستمر الأعمال المحفوظة المفوضة التي لا تحتاج قرارًا جديدًا، وتنتظر الأوامر الجديدة.
- تعطل قاعدة البيانات: يتوقف بدء عمليات ذات أثر خارجي حتى يعود تسجيل المحاولات؛ هذا عجز تنفيذ فعلي يمنع فقدان الحقيقة، وليس قاعدة جودة.

## النسخ الاحتياطي
استخدم آلية نسخ متسقة مع SQLite وWAL بدل نسخ ملف حي عشوائيًا. احتفظ بنسخ خارج المضيف وبمراجع الملفات الجاهزة والتهيئة اللازمة للاستعادة. تحدد أهداف فقدان البيانات ووقت الاستعادة مع المالك. استعادة نسخة قديمة تستلزم مصالحة النشر منذ وقت النسخة قبل فتح الإرسال؛ نسخة سليمة تقنيًا قد تفتقد منشورات حدثت بعدها.
