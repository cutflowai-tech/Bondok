# المراحل والتاسكات التنفيذية

كل مهمة تبدأ غير منفذة. المسؤول المقترح: منفذ المشروع، مع قرارات النطاق من المالك عند الحاجة. معيار الإنجاز في العمود الأخير هو المطلوب لإغلاق المهمة. التسلسل داخل كل مرحلة هو الافتراضي؛ لا تحذف خطوة قبل إثبات بديلها.

## P0 — حصر الواقع وتثبيت نقطة البداية

التبعية: لا توجد تبعيات؛ قراءة وتحقيق قبل التعديل.

| الحالة | المهمة | التنفيذ | معيار الإنجاز |
|---|---|---|---|
| ☐ | P0-01 | راجع المستودع والفرع والإنتاج والتعديل اليدوي في rules.py | تقرير فرق يحدد نسخة الإنتاج وكل اختلاف غير محفوظ. |
| ☐ | P0-02 | احصر workflows الثلاثة وكل trigger واستدعاء واعتماد | كل خطوة قديمة مرتبطة بوظيفة، ومسار كود، ومقابل مستهدف؛ يشمل الاستيراد ومهام المونتير والتنبيهات. |
| ☐ | P0-03 | راجع waset_ops وحدد ما يُعاد استخدامه وما يُنقل | قائمة احتفاظ/تعديل/حذف مع سبب؛ لا إعادة كتابة افتراضية. |
| ☐ | P0-04 | احصر قواعد العمل وموانع الصلاحيات في الكود والـprompts | جدول لكل قاعدة ومصدرها ومن يغيرها، مع تحديد رفض Topaz وصلاحيات البوت. |
| ☐ | P0-05 | تحقق من قدرات APIs الرسمية والحسابات الحالية | مصفوفة عمليات/صلاحيات/قيود/مراجع وتاريخ تحقق لـMonday وDropbox وInstagram وSlack، بما فيها ما لا تدعمه المنصة. |
| ☐ | P0-06 | احصر البيانات الجارية وخذ نسخة متسقة قابلة للفتح | جرد الحجوزات والمحاولات الغامضة والملفات، وتجربة استعادة معزولة بلا إرسال خارجي. |
| ☐ | P0-07 | سجّل سلوك النظام الحالي وأوامر التشغيل | نتائج اختبارات البداية وخريطة تشغيل كافية لإعادة إنتاج المشكلة. |

بوابة الانتقال: اكتمال كل المهام أعلاه بأدلة وعدم وجود عيب مفتوح يبطل نتيجة المرحلة.

## ما لا ندخله تلقائيًا في نطاق الهجرة

توسيع العمل إلى إدارة الإعلانات أو تحليلات الحملات، استبدال كل الكود، بناء واجهة جديدة بالكامل، أو الانتقال إلى بنية موزعة. الطلب الحالي ينقل القدرات القائمة ويكمل صلاحيات الإيجنت ويلغي n8n؛ القدرات الإضافية التي يطلبها المالك تضاف للنطاق صراحة.
