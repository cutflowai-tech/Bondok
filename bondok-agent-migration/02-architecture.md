# التصميم المستهدف

## شكل التشغيل
تطبيق Python واحد من المستودع الحالي، مع مسار تنفيذ أعمال خفيف ومسار منفصل لمعالجة الفيديو الثقيلة. يمكن تشغيلهما كعمليتين من نفس التطبيق تحت مدير خدمات يعيد التشغيل تلقائيًا. لا نحتاج microservices أو وسيط رسائل جديد لمجرد إزالة n8n.

```text
المالك عبر Slack / Monday
            ↓
  استقبال موثق + تسجيل طلب دائم
            ↓
  إيجنت: فهم، تخطيط، اختيار أدوات
            ↓
  أدوات التنفيذ داخل بندق ← قواعد المالك وذاكرة التشغيل
     ↓        ↓         ↓         ↓
  Monday   Dropbox   Instagram   Slack
            ↑
 مؤقّت دائم + عامل مهام + عامل معالجة فيديو
```

## دور الموديل
يفهم الطلب، يحدد النطاق، يستخدم أدوات القراءة والتنفيذ، يحل الحالات التي تتطلب تقديرًا، ويشرح النتائج. يستطيع الجدولة والنشر وتغيير القواعد فعلًا. لا يحتاج لتوليد كل طلب HTTP بنفسه؛ الأدوات تجمع خطوات العملية وتتكفل بتفاصيل المنصة.

تستخدم المهام المعتمدة بيانات وأوامر محفوظة. المؤقّت ينفّذ نشرًا سبق تفويضه بدون استدعاء جديد للموديل عند كل دقيقة. الموديل يدخل عندما يوجد طلب جديد أو قرار غير محسوم؛ تعطّل المزود لا يمحو التفويض ولا يوقف كل المهام الحتمية الجاهزة.

## الـModules
| Module | Interface الخارجية | Implementation الداخلية |
|---|---|---|
| Agent | استقبال طلب وإرجاع تقدم/نتيجة | فهم اللغة، اختيار الأدوات، طلب توضيح محدود |
| Operations | تنفيذ أمر والاستعلام عن نتيجته | الصلاحيات، قواعد المالك، منع التكرار، سجل القرار |
| Content | تجهيز نسخة واعتمادها | Dropbox وffprobe وffmpeg وأثر تغير الملف |
| Publishing | جدولة/إيقاف/نشر/مصالحة | الحجوزات، containers، المحاولات، نتائج الاتصال |
| Runtime | استلام مهمة وتشغيل المستحق | المؤقّت، حجز المهمة، إعادة التشغيل والمحاولات |
| Integrations | عمليات خدمات خارجية محددة | المصادقة، حدود المعدل، pagination، ترجمة الأخطاء |

واجهات الأدوات هي سطح اختبارات القبول. استخدم adapters للخدمات الفعلية ولبيئة الاختبار عند نقاط الاتصال الخارجية. لا تنشئ abstraction لكل دالة داخلية.

## مصدر الحقيقة
قاعدة بندق هي السجل التشغيلي الأساسي. Monday واجهة إدخال وعرض. تعديل الإنسان يصبح طلبًا محفوظًا مع نتيجة قبول أو رفض محددة. Instagram مصدر أدلة النشر الخارجي. الملفات المعتمدة تُعرّف بمعرف النسخة والبصمة، وتُحفظ النسخة الجاهزة بحيث لا تتغير أثناء النشر.

SQLite مقبولة مبدئيًا على قرص محلي وسيرفر واحد إذا نجحت اختبارات التزامن والاستعادة. الانتقال إلى Postgres قرار لاحق إذا لزم تشغيل متعدد المضيفين أو ظهرت حدود فعلية. الاستعادة جزء من التصميم، وليست تصديرًا اختياريًا للبورد.

## المزامنة
احفظ نتيجة العملية ومهمة تحديث الواجهات في معاملة محلية واحدة. عامل مزامنة مستقل يحدّث Monday وSlack ويحاول مجددًا عند الانقطاع. اكتب حقول العرض التي يملكها النظام فقط. الحقول المشتركة أو تعديلات المستخدم تُدار بإصدار متوقع أو طلب مستقل؛ القراءة ثم الكتابة وحدهما لا تضمنان منع التصادم.

استقبال تغييرات Monday يكون عبر webhooks إذا كانت مدعومة ومناسبة بعد التحقق، مع مراجعة دورية لتعويض الأحداث الضائعة. لا توجد إعادة إرسال دورية لكل البورد إلى الموديل.

## الاعتمادية
حجز مهام دائم مع مهلة واستعادة بعد الانقطاع؛ حماية من تكرار التنفيذ بين نسختين؛ مهلات لكل اتصال؛ إعادة محاولة بتأخير للأعمال الآمنة؛ مصالحة خاصة بالنشر الغامض. حذف n8n لا يعني حذف هذه المسؤوليات، بل تجميعها داخل بندق.
